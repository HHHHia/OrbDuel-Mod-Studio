# 团队交接：理解、接手和继续贡献

这是可继续开发的 C++17 工程，包含游戏、编辑器、原生模组 SDK、示例、教程和测试。分享快照保留许可证与来源说明；原始项目的已有贡献不会因为打包而改写。

建议接手的人先按 MACOS 或 QUICK_START 启动，再完成下面一个独立任务。任务认领表示后续实际工作，不自动记为已经实现。各成员使用自己的 Git 身份提交，并在演示中解释自己修改的代码与验证结果。项目使用过编码代理辅助，介绍开发过程时保留这一事实。

| 可认领的工作 | 应交付的结果 | 演示时解释什么 |
|---|---|---|
| 新的 C++ 模组 | 从模板制作一种新机制，参数、说明、示例地图 | 回调、参数、实体查询及效果如何连接 |
| 召唤物新 AI | 修改追踪控制器，在现有护卫之上实现巡逻、撤退或新的协作策略 | 如何选敌人、如何移动、何时销毁能力 |
| 地图与规则组合 | 用传送门、熔岩、区域治疗或召唤器组合一张地图 | 种子与分享码分别保存什么，规则如何影响玩法 |
| 教程和交互改进 | 实际走一遍新手流程，改进提示与图示 | 哪一步会让新手卡住，改动如何解决 |
| 角色机制与平衡分析 | 保留特色机制，明确场地、样本、训练角色排除规则 | 为什么不能只拿总胜率判断所有自定义玩法 |

不设目标日期。先写一小段任务说明，再用自己的分支做实际改动；完成后提交 PR，附效果或验证记录。原有贡献保持真实；新增贡献由成员自己的改动、提交和演示记录体现。

## 代码入口

- `src/game/Studio.cpp`：工作台装配、界面、输入和绘制。
- `src/match/Simulation.cpp`：固定步、原生模组 Host、实体及能力生命周期。
- `src/match/Match.cpp`：HP、伤害、队伍、技能调度与胜负。
- `src/mods/PluginManager.cpp`：Windows/macOS 原生库加载和用户模组覆盖。
- `mod-sdk/examples/`：七个独立 C++ 示例及能力作者起步模板；`mod-sdk/template/` 是自包含工程。
- `content/`：角色、内置技能、地图、字体、音效；修改内容先看 CONTENT_FORMAT。

当前已实现和未验证边界见 STATUS、VALIDATION、MACOS；模块不变量见 MODULE_CONTRACTS。不要把“接口可编译”“测试通过”“画面能打开”“Mac 实机可用”写成同一件事。

C++ 自建能力入口见 docs/CUSTOM_ABILITIES.md；时间回溯与护卫已经实现，可从 ability/rewind/guardian 模板继续创作。新建能力的触发、选敌与效果由模组 C++ 自己决定，无须在引擎中按技能名添加分支。

源码交接包可用 `cmake -P tools/share-source.cmake` 从已提交、无未提交改动的工作区生成。默认输出在 `dist/OrbDuel-source-share`，也可用 `-DOUTPUT=<新目录>` 指定位置。
