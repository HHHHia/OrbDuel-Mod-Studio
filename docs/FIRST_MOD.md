# 第一个模组：从复制到游戏中使用

目标：做出一份独立的旋风模组，先用默认强度运行，再改成反向旋转。整个过程中不需要修改或重新编译游戏源码。

## 准备

- 使用包含本轮模组工具的游戏发布包。源码用户先在仓库根目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -SkipRun`，之后游戏位于 `build/bin/orbduel.exe`。
- 安装 Visual Studio 2022 或 Build Tools，勾选“使用 C++ 的桌面开发”和 CMake 工具。模组是 C++ DLL，需要编译器；脚本会自动寻找工具，不要求手动配置 PATH。
- 以下第一条命令在游戏目录或仓库根目录的 PowerShell 中执行；两种目录都包含 `mod-sdk/`。

## 1. 复制模板

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\mod-sdk\new-mod.ps1 -Id my-vortex -Name "我的旋风"
```

这等同于复制模板，并自动带上 SDK 头文件和许可证。默认产生 `user/mod-projects/my-vortex/`；该工程可以整个移动到别处，仍能独立构建。也可以给命令追加 `-Destination "自己的工程文件夹"`。已有目录不会被覆盖。

打开生成的工程，主要文件是：

| 文件 | 用途 |
| --- | --- |
| `mod.json` | 名称、标识和默认参数，第一步只需要改它 |
| `my_mod.cpp` | 旋风行为，之后写新逻辑时再改 |
| `build-install.cmd` | 双击构建并安装 |
| `include/orbduel_mod.hpp` | 随工程提供的 SDK |
| `SDK_LICENSE.txt` | 随模组保留的 SDK 许可证 |

想做第二个模组，再运行创建命令并使用另一个 Id，例如 `other-vortex`。完整类型名会自动成为 `other-vortex.vortex`，无需在 C++ 里同步改名。

## 2. 认识配置

打开 `mod.json`，内容类似：

```json
{
  "id": "my-vortex",
  "name": "我的旋风",
  "library": "my-vortex.dll",
  "typeId": "vortex",
  "typeName": "我的旋风",
  "defaults": { "strength": 300 }
}
```

`name` 是模组工坊中的名称，`typeName` 是编辑器工具箱中的名称。`strength` 是默认旋转强度；正负值的方向相反，绝对值越大施力越强。数值不加引号。

先保留 300。标识 id 和 typeId 用小写字母开头，后面可以用字母、数字、短横线和下划线。创建后通常只改显示名称与参数；想做另一份模组，用新的 Id 创建另一份工程。

## 3. 一键构建安装

双击工程中的 **build-install.cmd**。

首次会让你选择要安装到的 `orbduel.exe`。源码用户选择 `build/bin/orbduel.exe`；发布包用户选择包里的游戏程序。脚本会构建这一个模组，并放到该游戏的 `mods/my-vortex/`，不会重新构建游戏。

看到“安装成功”即可。下次双击会记住这个游戏位置；如果游戏被移动，再次选择新位置即可。命令行也可以指定或更换目标：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\user\mod-projects\my-vortex\build-install.ps1 -GameDirectory ".\build\bin"
```

上面的命令在仓库根目录执行。若当前就在模组工程内，将 `-File` 后的脚本路径改为 `.\build-install.ps1` 即可。

## 4. 在游戏里使用

1. 打开游戏，进入“模组工坊”，点击 **重新加载模组和内容**。如果游戏一直开着，也只需要点这个按钮。
2. 工坊列表应出现“我的旋风”。进入“地图编辑器”，工具箱也会出现同名机关。
3. 为了容易观察，先将“障碍组”和“机关组”设为 0，再按种子生成空场；然后在球的出生位置旁边放一个旋风。
4. 选中旋风，在右侧把半径调到 **200**。旋转强度控件由模组自动注册，默认应为 **300**。
5. 点击“测试地图”，球进入范围后会受到切向加速度。返回编辑器时，地图草稿仍在。

## 5. 改参数，再安装与重新加载

退出测试，回到模组工程，把配置改成：

```json
"defaults": { "strength": -600 }
```

再次双击 `build-install.cmd`。使用本轮新版游戏时，即使旧旋风仍已加载，也可以安装；看到“安装成功”后回到工坊点重新加载。

**新放置一个旋风**，它的默认强度应为 -600，测试时方向与之前相反，施力也更强。

旧地图对象已经保存了自己的参数，重新加载不会覆盖它们。若要改变旧对象，直接把右侧“旋转强度”改成 -600，或者删除后重新放置。只改某张地图里的实例参数时，不需要编译模组。

## 6. 做新逻辑与分享

要新增行为，修改 `my_mod.cpp` 中的 `Vortex::step`，仍用同一个双击入口构建安装。它通过 SDK 查询球的位置、判断范围，再施加加速度，不依赖游戏内部类。更多接口见 [模组技术说明](MOD_STUDIO.md)。

可以把公共素材放到工程的 `assets/`，访问路径相对模组目录，例如 `assets/example.png`。

分享 **build/package/my-vortex/** 整个文件夹，包含 DLL、mod.json、SDK 许可证及可选素材。接收者把它放进自己的游戏 `mods/` 再重新加载。地图分享码需要另行分享；它不会携带 DLL。

不要分享工程的整个 build 目录或 `.orbduel-user.json`。后者只记录你本机的游戏位置，已经被工程的 `.gitignore` 排除，也不会进入模组安装包。

## 遇到问题时

| 现象 | 处理 |
| --- | --- |
| 找不到编译工具 | 在 VS 2022 安装器中添加 C++ 桌面开发和 CMake 工具 |
| 编译失败 | 查看双击窗口中的错误；修正后再试，原来的安装不会被替换 |
| 搬动已构建工程后提示旧路径 | 只清理模组工程内生成的 build 文件夹，保留源码和 include，再双击构建 |
| 提示 DLL 被锁住 | 目标可能是旧版游戏；更新到本轮游戏，或先退出旧游戏再安装 |
| 工坊有模组，编辑器找不到名称 | 确认已重新加载，寻找配置中的 typeName；工坊显示的是 name |
| 新默认参数没有改变旧机关 | 属于正常行为：改右侧参数，或重新放置一个机关 |
| 旋风看起来没效果 | 放在球附近并把半径设为 200，确保球进入范围，且强度不是 0 |

自动测试也会走完整流程：复制到带空格和中文的工程目录、双击入口安装、宿主持有旧 DLL 时再次安装、同进程重新加载、验证强度反向、两模组共存，以及编译失败后旧安装仍能运行。
