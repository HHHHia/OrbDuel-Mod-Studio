# 模组与地图工作台 / Mod Studio

整合回归包含独立 SDK 模板加载。模板编译后，可运行
`build/Release/orbduel_integration_tests.exe content build/bin/mods build-template/package`，
检查外部旋风 DLL 是否通过 SDK 改变实际物理，无需将该行为链接进宿主。

## 1. 普通玩家

在“地图编辑器”左边选对象，点击画布放置，再选中对象修改右侧属性。位置、半径和朝向是公共属性，剩余控件由模组作者声明，游戏自动生成。

传送门至少放置两个，入口的“关联出口”选择另一扇门。出口朝向决定按出口方向传送时球的运动方向；速度倍率决定穿过后的速度。引力场可以吸引或排斥，也能设置“跟随左方/右方角色”，使其成为附着在角色身上的能力。弹射板可以附带短时护盾。

“按种子生成”产生镜像场地。生成后仍可手工调整。种子用于重新生成初始布局；分享码保存的是实际地图快照，因此拖动过的位置和参数也能还原。

在“地图文件”输入文件名即可另存。分享时复制 `OD1:` 开头的文本，对方在“分享码”窗口粘贴并导入。代码中不包含 DLL 或图片，对方需另行复制对应模组文件夹。没有账号、服务器、签名、哈希或版本锁。

## 2. 第一个 C++ 模组

先按 [第一个模组实操教程](FIRST_MOD.md) 完成复制、参数修改、一键安装和游戏重新加载。

`mod-sdk/new-mod.ps1` 会带上 SDK 头文件和许可证，生成的工程不依赖原 SDK 位置。配置集中在 mod.json；类型 ID 自动组合为 `<id>.<typeId>`。双击 build-install.cmd 后选择目标游戏，即可构建安装；后续会记住位置。

也可保留旧的 CMake 方式单独构建 template，生成目录仍为 build/package/<id>。运行中的新版游戏使用 DLL 副本，不会锁住安装文件；重新加载前仍会销毁预览和比赛。默认参数改变只影响新对象，已有对象保留自己的参数。

## 3. 注册一个行为

SDK 的 `Behavior` 是便捷基类；`behavior<T>` 把 C++ 方法转换为宿主的函数表。无需继承游戏内部类，也无需链接游戏的静态库或 SDL。

- `step(float dt)`：每个固定物理步调用，dt 为 1/120 秒；用于持续加速度或自己的计时器。
- `event(const Event&)`：收到碰撞、区域进入/离开、实际伤害等事件；按 `event.object == id` 识别自己的区域事件。
- `draw(const Draw&)`：通过画圆、线、矩形和图片展示能力；不在这里修改游戏状态。
- 未使用的方法可省略，基类提供空实现。实例中的 C++ 字段用于保存冷却和充能状态。

用 `ORBDUEL_MOD_EXPORT void orbduel_register(Registrar*)` 注册类型。`Type` 声明需在 DLL 加载期间有效；注册时宿主复制函数表，参数数组和文字可使用静态存储。

`Param` 支持数字、整数、开关、选项、颜色、对象引用、文字。数值范围用于滑块和拖动，不是统一的游戏平衡限制。Choice 选项用 `|` 分隔；颜色为四个 0–1 分量。`placement=1` 可被生成器单独放置，`placement=2` 成对放置，并自动关联名为 `target` 的对象引用参数；0 为只手工放置。

## 4. 世界接口

所有坐标是场地世界坐标，左上角为原点，x 向右、y 向下；角度按度数，正值顺时针。

| 接口 | 行为 |
| --- | --- |
| `entityCount / entityAt` | 查询本局实体的 ID、位置、速度、碰撞半径、HP 和护盾；失效实体不要继续作用 |
| `getObject` | 按对象 ID 查询机关位置、半径、朝向和附着对象 |
| `number / text / color` | 读取本实例参数；`Behavior` 直接提供 number/color 包装 |
| `setPosition / setVelocity / accelerate` | 移动实体、设置速度、添加加速度；传送后宿主将球推回场地内 |
| `damage / heal / shield` | 通过比赛的统一入口改变状态；damage 提供来源、目标、伤害和原因；额外伤害会消耗护盾 |
| `spawn / remove` | 创建、移除机关；在步末实际提交，spawn 返回预留 ID |
| `emit` | 发布自定义命名事件，下一个固定步处理，防止回调递归 |
| `random / time` | 获取本局有种子随机数和模拟时间，不受渲染帧率影响 |

默认有两个战斗实体，entityAt 参数是查询索引，操作时使用返回的实体 ID。机关和战斗实体是不同的 ID 空间，不要混用。对象引用在运行前后可能被作者删除，查询失败时跳过即可。

内置事件：`enter`、`stay`、`leave`、`hit`、`wall_bounce`、`damage`、`skill_cast`、`death`、`round_end`。区域事件的 `a` 是进入者，`object` 是区域 ID；damage 的 `a/b` 是来源和目标，value 是实际扣血量，cause 区分 contact/environment/作者自定原因。碰撞事件表示双方接触，不预设某一方是唯一攻击者。

DLL 使用简单结构与函数表，创建者销毁自己的实例；不跨 DLL 传递 STL 容器或释放对方创建的内存。当前以统一的 MSVC 2022 x64 工具链构建。不做战斗中卸载：回到模组工坊重新加载时，先销毁预览与比赛，再卸载旧 DLL。

## 5. 示例如何复用

- `examples/portal.cpp`：区域进入、对象引用、传送、速度方向、冷却、颜色与自定义事件。
- `examples/gravity.cpp`：持续力场、吸引/排斥、作用对象和范围。
- `examples/launch.cpp`：区域进入后弹射，并可附带护盾。
- `template/my_mod.cpp`：旋风模板；`examples/summon.cpp`：创建战斗实体并绑定追踪能力，可用 `-Kind summon` 复制。
- `examples/lava.cpp`：范围环境伤害，每 0.25 秒结算；示例地图 content/studio/lava-pool.json。


技能式能力可把对象附着在角色上，再根据事件与自己的冷却逻辑施放。需要引擎尚未开放的物理量或绘制能力时，扩展 SDK；不要求所有可能机制都塞进预设效果枚举。

## 6. 存档与重新加载

游戏默认保存最近一次草稿到 `user/last-scene.json`。用户地图和分享码是普通文件，可离线复制。重新加载按钮重读角色、技能、模组，失败保留已有内容数据并显示原因；DLL 加载失败则在模组工坊列出问题。开始测试持有内容快照，返回编辑器后草稿不受模拟状态影响。

素材路径相对模组目录。绘制图片的参数为世界坐标中心、世界尺寸、角度和颜色。模组资源要随文件夹一起分发。

## 7. 战斗实体与能力绑定

额外的 EntityApi 开放创建、销毁、按 ID 查询、队伍信息和能力绑定。分身通过统一物理与 HP 管线移动、碰撞、受伤和死亡；示例及可复制的新手教程见 [战斗实体与分身模组](COMBAT_ENTITIES.md)。内置召唤试验地图为 content/studio/summons.json。
